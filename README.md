# 🍺 1708 — Система управления заказами бара

Real-time система для бара: приём заказов, управление очередью, учёт склада и гостевое меню по QR-коду.

> Локальная версия после аудита использует серверные операции Firebase Functions (`functions/`) для заказов и изменений столов. Хранение v2 разделяет рабочие данные и архив. Фронтенд требует переноса базы и согласованной публикации функций и правил: порядок в [RELEASE.md](RELEASE.md). Общий вход персонала сохранён. Результаты проверок, изменения и ограничения описаны в [FIXES.md](FIXES.md).

После перехода на v2 менеджер может включить в настройках режим обслуживания. Он атомарно останавливает новые заказы, изменения персонала и архивные задания, но сохраняет чтение данных и восстановление подтверждения уже принятой операции. В интерфейсе остаётся постоянная панель для возобновления работы.

## Проверки

- `npm test` — быстрые проверки и браузерные сценарии Playwright.
- `npm run test:integration` — Auth, Database и Functions на локальных эмуляторах demo-bar-1708; запуск требует Node.js 22, Java 21 и Firebase CLI. Порядок подготовки указан в [FIXES.md](FIXES.md#локальный-запуск-интеграции).
- `npm run test:rehearsal -- prepared-v2.json` — загрузить подготовленную копию базы только в demo-эмулятор, проверить параллельные заказы, уникальность номеров, неизменность старых заказов и блокировку операций режимом обслуживания.
- `npm run test:hosting` — собрать `dist`, запустить Firebase Hosting Emulator и подтвердить доступность сайта при недоступности отчётов, тестов, скриптов и Functions.
- `npm run emulators` — тот же согласованный demo-стенд для ручной работы.
- `npm run test:load` — локальная нагрузка с 0/1000/5000 архивными заказами и небольшим рабочим набором; все профили прошли.
- `npm run test:load:live` — проверка компактизации на 0/1000/2000 закрытых заказах текущего дня. Все закрытые заказы переносятся из рабочего набора, после чего 14 параллельных операций проходят без ошибок; измерения приведены в [отчёте](audit-2026-09-19/REPORT.md).
- `npm run test:mobile` — сценарии Chromium/Pixel 7 и WebKit/iPhone 13; движки устанавливаются через `npx playwright install chromium webkit`. Это эмуляция, физические телефоны проверяются отдельно.
- `npm run prepare:storage -- --input export.json --output migrated.json --report migration-report.json` — подготовить перенос полного локального экспорта в v2, не меняя исходник. Обратный перенос: тот же вызов с `--rollback` и свежим v2-экспортом.
- `npm run verify:storage -- --source export.json --migration migrated.json --migration-report migration-report.json --output verification.json` — независимо сверить хеши, каждый заказ, архивные суммы, дубли и точность обратного переноса.
- `npm run verify:rollback -- --source fresh-v2.json --rollback rollback.json --rollback-report rollback-report.json --output rollback-verification.json` — отдельно проверить подготовленный откат: каждый заказ, отсутствие дублей, контрольные суммы и полное совпадение результата.
- `npm run build` — собрать в `dist` только разрешённые файлы сайта. Тесты, отчёты, скрипты и Functions в Hosting не попадают.
- `npm run preflight:release -- ...` — сформировать блокирующий предрелизный отчёт с двумя совпадающими вводами Firebase project ID, подтверждённым числом замечаний аудита и отпечатками базы, сайта и серверного кода. Полная команда приведена в [RELEASE.md](RELEASE.md).
- `npm run verify:release -- ...` — непосредственно перед публикацией повторно сверить предрелизный отчёт с текущей базой, сборкой, правилами и Functions. Любое изменение после создания отчёта блокирует выпуск.
- `npm run audit:data -- --input export.json --output report.json` — проверка локального полного JSON-экспорта RTDB без изменения исходных данных. Отчёт должен быть новым отдельным файлом.
- `npm run summarize:data -- --input export.json --audit audit.json --migration-report migration-report.json --output summary.json` — обезличенная сводка качества старых заказов по состояниям сессий и влиянию замечаний на первичный архив. Исходные данные не изменяются.

В `.github/workflows/tests.yml` настроен прогон обычных, мобильных, hosting- и интеграционных проверок для push и pull request. Он не публикует сайт и не использует рабочую базу. Первый запуск в GitHub выявил отсутствие локальных тестовых Web Push-ключей; стенд теперь создаёт одноразовую пару только для demo-проекта и удаляет её после завершения. Повторный запуск для коммита `67598a4` прошёл полностью.

## Роли

| Роль | Что видит |
|------|-----------|
| **Бармен** | Очередь заказов, кнопки «Начал» / «Готово» по каждой позиции |
| **Официант** | Новый заказ, список готовых к выдаче, кнопка «Отнёс», вызовы от гостей |
| **Менеджер** | Всё вышеперечисленное + статистика, редактор меню, управление столами |

## Основные функции

- **Real-time синхронизация** — заказы обновляются мгновенно на всех устройствах через Firebase
- **Компактный рабочий набор** — закрытый счёт сразу переносится в архив; экран закрытых счетов загружает его по дате, а переоткрытие возвращает исходный снимок для исправлений
- **Гостевое меню** — гость сканирует QR, выбирает позиции и отправляет заказ
- **Учёт склада** — атомарное списание при заказе; отмена возвращает только ещё не использованные позиции
- **Мгновенная доставка** — пиво, напитки и закуски официант может сразу отметить как доставленные
- **Фоновые уведомления** — установленное PWA получает новые заказы и вызовы официанта через Web Push, даже когда приложение не открыто. Бармен получает заказы, официант — вызовы, менеджер — оба типа; используется общий вход персонала
- **Вызов официанта** — гость вызывает официанта кнопкой из гостевого меню
- **Пробковый сбор** — добавляется к счёту стола одним нажатием (100 / 700 / 1000 ₽)
- **Добавки к чаю** — чабрец, лимон, мята (+50₽) и общий счётчик кружек на стол
- **Опции позиций** — к любой позиции меню можно задать выбор (например: с лаймом / без)
- **Квиз** — генерация QR-кодов для всех столов для печати (режим квиз-бара)
- **Сброс счётчика заказов** — номера заказов можно обнулить вручную (только менеджер)
- **PWA** — устанавливается на телефон как приложение
- **Офлайн-защита** — при потере интернета показывается предупреждение, ошибки записи не теряются молча

## Стек

- **Firebase Realtime Database** — хранение заказов, меню, столов
- **Firebase Auth** — общий вход персонала и отдельная анонимная сессия гостя
- **Firebase Functions** — проверка и атомарное выполнение операций заказов и столов
- **Vanilla JS (ES Modules)** — без фреймворков и сборщиков
- **PWA** — Service Worker, Web App Manifest

### Фоновые уведомления на iPhone

Требуется iOS 16.4 или новее. Откройте сайт в Safari, нажмите «Поделиться» → «На экран Домой», запустите 1708 с появившейся иконки, войдите и выберите роль. Затем нажмите кнопку `🔔 Ув. вкл.` и разрешите уведомления. После успешной подписки кнопка показывает `🔔 Фон вкл.`. Если сайт открыт обычной вкладкой Safari, приложение само подскажет сначала добавить его на экран «Домой». Требования соответствуют [Web Push для Home Screen web apps](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
