# Удобство работы со счетами — APK 0.8

## Что изменилось для сотрудника

- Запуск открывает вход/список счетов. Автономная проверка одного товара доступна в «Настройки → Проверка отдельного товара»; возврат сохраняет текущий вход сотрудника.
- По умолчанию читаются два отдельных дня: сегодня и вчера, определяемые по Москве. Счета не переписываются на сегодняшнюю дату и не объединяются по одинаковому номеру стола. Старую дату можно выбрать календарём; доступны быстрые пункты «Сегодня» и «Вчера».
- Закреплены дата, поиск по номеру стола или названию товара, фильтры «Все / Новые / Открывались / Проверить». Указаны количества счетов и сумма выбранного перечня. Номера столов сортируются как числа внутри дня (2 перед 10).
- Карточка показывает стол, сумму, исходный день, статус и краткий состав. «Ранее открыт» не означает «не оплачен»: реальное состояние по-прежнему проверяется в кассе перед продолжением.
- Обновление каждые 10 секунд работает в фоне. Поиск, фильтр и прокрутка не сбрасываются; неизменившийся список не пересоздаётся. Запоздалый результат запроса не заменяет экран счёта или настроек. При ошибке прежний список остаётся с явной отметкой, что свежего подтверждения нет.
- На счёте крупно показаны итог и дата, одинаковые кассовые карточки сгруппированы прежним `CashReceiptPlan`. Основное действие и две вторичные кнопки закреплены внизу. Возврат из «Продажа», открытого для конкретного счёта, повторно проверяет его реальное состояние; открытие произвольного текущего чека не привязывается к случайному столу. Кнопка Android «Назад» возвращает к счетам; при незавершённой операции не прерывает попытку открытия. Выход из аккаунта подтверждается отдельно.
- Передача каталога, выход, версия, инструкция отложения и проверка отдельного товара находятся в настройках.

## Обновление неизменившегося снимка без телефона

У просроченного `queued`-счёта есть «Проверить свежесть». До обновления timestamp приложение проверяет открытый исходный визит и sid, полное совпадение строк/количеств/цен текущих заказов, наличие сохранённых цен вместо оценок меню, актуальные карточки кассы и совпадение итога. Условный PUT разрешён только для того же digest и состояния `queued` без `needsRefresh`. Конкурирующее изменение отклоняется по ETag. Состав, дата, sid и история попыток не меняются.

Дозаказ, изменение цены, закрытый визит, старый формат или оценочные цены требуют обновления на сайте. Открытый/неизвестный/очищенный счёт этим методом не разблокируется. Обновление свежести не вызывает SDK, не оплачивает чек и не закрывает стол. При последующем открытии повторяются все прежние проверки и серверное резервирование.

## Визуальные решения

Светлый фон #F4F6F8, белые поверхности, основной текст #1C2832, вторичный #54636F, янтарный #FFB224 для действий и выбранного фильтра. Зелёный/красный дополняют текст статуса, а не заменяют его. Системный Android sans-serif сохраняет привычную читаемость на терминале; суммы 30sp, заголовки 23sp, кнопки 16sp с минимальной высотой 52dp. Длинные названия обрезаются только в кратком списке, полный состав виден внутри счёта.

## Проверка и границы

Unit tests покрывают московскую полночь/смену месяца при другом часовом поясе устройства, строгий выбор даты, поиск с ё/е, разделение состояний и дней, денежные копейки, сортировку столов, конфликт обновления/смену digest и запрет обновлять начатую попытку. Сборка и Android Lint выполняются скриптом `build.ps1`.

Физического терминала или Android-эмулятора с Evotor POS в среде сборки нет. Фактическую отрисовку, возврат из «Продажа» и полный сценарий отложения нужно подтвердить после обновления APK с сохранением данных. Команды парковки SDK не добавлены: отложение по-прежнему явно требует ручного «Очистить» в «Продажа». Runtime сайта, права Firebase, команды оплаты и печати не менялись.
