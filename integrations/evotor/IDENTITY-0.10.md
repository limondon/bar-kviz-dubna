# Постоянная регистрация кассы, 0.10

Причина дублей: до 0.10 `device-id` был случайным UUID только в SharedPreferences. Обычное обновление сохраняло его, удаление данных или переустановка создавали новую регистрацию. Модель и одинаковые каталоги не доказывают принадлежность одному физическому терминалу.

0.10 читает Settings.Secure.ANDROID_ID и сохраняет только SHA-256 с пространством имён приложения. Привязка `config/evotor/v1/terminalLinks/<android-hash>` указывает на прежний `devices/<device-id>`. Первое обновление сохраняет существующий UUID вместе с соответствиями. После переустановки приложение получает этот UUID из привязки. Создание защищено Firebase ETag: конкурентная регистрация не перезаписывает победившую. Ошибка чтения не создаёт запасную регистрацию. Неизвестный/нулевой/общеизвестный общий Android ID не используется; существующая установка продолжает работать с предупреждением в настройках, новая регистрация блокируется.

Android ID сохраняется после переустановки при прежних пакете, подписи и пользователе Android. Сброс терминала к заводским настройкам, другой пользователь или смена ключа подписи могут изменить его. Это не обещание сохранения после полного сброса устройства. Источники: [Android Settings.Secure](https://developer.android.com/reference/android/provider/Settings.Secure#ANDROID_ID), [поведение Android 8](https://developer.android.com/about/versions/oreo/android-8.0-changes#privacy-all).

`devices/<id>/registration` содержит версию приложения, время экспорта, ключ привязки и флаг `archived`. Экспорт активной кассы снимает архивный флаг; он не меняет настройки товаров. На сайте архивные регистрации скрыты по умолчанию, доступны через «Показать архив» и могут быть возвращены. Архивирование меняет только registration, не удаляет каталог, соответствия, передачи или журнал чеков. Разные терминалы не объединяются по названию/каталогу.

Устанавливать APK поверх существующего приложения, сохраняя данные. Один раз открыть «Счета с сайта» с интернетом: привязка создаётся после входа, каталог и версия отправляются автоматически. В настройках видны номер регистрации и состояние привязки. Физическая переустановка и Android ID конкретного Эвотора требуют проверки на терминале; локальные unit tests проверяют миграцию старого UUID, повторный вход без локального ID, два разных терминала, гонку, повреждённую привязку и сохранность данных при возврате из архива. Финансовый протокол не изменён.
