## Состав

- Черновик официанта сохраняется при вводе, выборе стола и подтверждении выбора из меню. Восстанавливается после перезагрузки той же вкладки. Очищается после подтверждённого создания заказа. При закрытии вкладки сохранность sessionStorage не гарантируется.
- В корзине гостя виден выбор количества кружек. Удаление последнего чая сбрасывает кружки; они передаются персоналу в существующем формате заказа.
- Первый заказ после пустой очереди вызывает звук; повторное обновление того же заказа не звучит. Звук можно включить даже при запрете системных уведомлений. При включении воспроизводится пробный сигнал. Панель требуется оставить открытой.
- В WebKit устранена горизонтальная прокрутка контейнера при переключении экранов. Повторный быстрый переход не скрывает активный экран старым таймером.
- При загрузке отключены удаление некорректных старых заказов, автоматическая реконструкция сессий и заполнение пустой базы встроенным меню. Некорректные заказы пропускаются при отображении с предупреждением, исходные записи сохраняются.

## Границы

Это выпуск отдельных клиентских улучшений, а не бесплатная реализация всей серверной версии. Здесь нет архива v2, расписания архивации, серверного режима обслуживания, Web Push для закрытого приложения, серверной проверки цен и гарантии повторной отправки без дублей. Создание заказа и изменение остатков сохраняют прежние раздельные записи; при обрыве связи и одновременных действиях остаются ограничения прежней схемы.

Доступ к Firebase по-прежнему определяется существующими правилами базы. Старый `database.rules.json` оставлен как часть исходной версии, его не следует публиковать этим выпуском или считать заново проверенной схемой безопасности.

## Комплект

`npm run build` собирает только 28 публичных файлов в `dist-spark`. В комплект не попадают резервные копии, ключи, тесты, отчёты и серверные файлы. Сборка отклоняет зависимости от Functions и путей v2; контрольные суммы записывает в `.release/spark-build.json`. Первый выпуск использовал кэш `bar-spark-v1`; исправление очистки вызовов от 25 сентября — `bar-spark-v2`; защита сохранения меню от 26 сентября — `bar-spark-v3`.

Сохранение меню выполняет транзакционную проверку актуальности загруженной копии. При конфликте с другим редактором или изменением остатков операция отклоняется с сообщением вместо перезаписи новых данных. Перед продолжением редактирования нужно закрыть старые вкладки на всех устройствах и открыть обновлённый сайт: защита действует в новом клиенте и не блокирует записи из оставшихся старых версий. Этот выпуск не восстанавливает категории из резервной копии и не меняет рабочие цены или остатки при публикации.

`firebase.json` содержит только Hosting из `dist-spark`, однако действующие адреса находятся на GitHub Pages и Vercel. Публикация в Firebase Hosting сама по себе их не обновит; создавать третью копию для этого выпуска не требуется. В выпуске нет подключения платёжного аккаунта, новых облачных сервисов, импорта данных или публикации правил. Работа базы в рамках Spark остаётся ограничена квотами этого тарифа; фактический тариф кабинета при проверке публичных файлов не определялся.

## Публикация

Адреса и версия клиента до обновления подтверждены. GitHub Pages ранее публиковал корень `main`; для этого выпуска используется GitHub Actions с артефактом `dist-spark`. Vercel связан с этим же репозиторием; последняя успешная Production-сборка перед выпуском — `39b85a6`. `vercel.json` задаёт сборку и тот же каталог `dist-spark`. Workflow выполняет тесты до публикации GitHub Pages. Этот клиент рассчитан на корневые `orders`, `tables`, `menu2`; его нельзя направлять на уже перенесённую v2-базу с `live/`.

Текущие публичные комплекты сохранены. Попытка свежего экспорта базы 24 сентября не удалась: Firebase CLI не авторизован. Старый экспорт от 20 сентября не подтверждает сегодняшнее состояние базы. Это ограничение сообщено пользователю; публикация только клиентских файлов не включает операции с базой, а свежий экспорт остаётся обязательным перед будущей миграцией данных. Правила и данные для этого клиентского выпуска не меняются. После публикации проверить файлы обоих сайтов и загрузку страниц; реальный заказ и слышимость звука при свёрнутой панели на ноутбуке требуют проверки сотрудником. При откате вернуть предыдущие файлы сайта на обеих площадках, не импортируя старый экспорт поверх новых заказов.
